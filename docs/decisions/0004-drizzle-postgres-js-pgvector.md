# 0004. Drizzle + postgres-js; pgvector in the same database

## Status

Accepted

## Context

bhidubot stores meeting transcripts, notes and their embeddings for semantic retrieval. We need a typed Postgres
access layer for Bun, a migration workflow, and a place to keep vectors. Retrieval is always scoped to a user or team,
so each query searches a small candidate set rather than the whole corpus.

## Decision

- Drizzle ORM with the postgres-js driver (`drizzle-orm@^0.45`, `postgres@^4`) in `packages/db`.
- Migrations are generated by drizzle-kit into `packages/db/drizzle` and applied with `runMigrations`. The first
  migration begins with `CREATE EXTENSION IF NOT EXISTS vector;`.
- Embeddings live in the application database as pgvector columns, not in a separate vector service.
- `createDb` passes the schema to Drizzle so relational queries (`db.query.<table>`) are available.

## Why

- Scoped retrieval means small candidate sets, so exact search is fast and an ANN index is optional.
- One transaction covers a row and its vectors, so they cannot drift apart.
- Cascade deletes remove vectors when a meeting, user or team is deleted.
- Ordinary SQL filters combine with vector similarity, and hybrid search with Postgres full-text is possible in one
  query.
- One fewer vendor to run, secure, pay for and mock in tests.

## Pros

- Single source of truth, one backup, one local container (`pgvector/pgvector:pg17`).
- Drizzle is SQL-shaped, typed, and has a native `vector` column type.

## Cons

- Vectors bloat the database and its backups.
- HNSW index builds consume the application database's CPU and RAM.
- The embedding dimension is fixed per column; changing models means a migration and re-embedding.
- No Prisma-style high-level abstractions; more SQL knowledge is expected.

## Alternatives considered

- Pinecone (used by meeting-bot69): extra vendor and cost, no transactional link to rows, deletes must be mirrored.
- Prisma: no native vector type in v6, so it needs `Unsupported` columns plus raw SQL.
- Kysely: a good query builder, but no schema/migration tooling that matches Drizzle's, and no vector support built in.

## Consequences / follow-ups

- Later tasks add tables (Better Auth, meetings, chunks with `vector` columns) to `packages/db/src/schema`.
- Every package with DB tests uses a `bunfig.toml` preload that calls `runMigrations(DATABASE_URL_TEST)` and
  `resetTestDb` between tests.
- Revisit an external vector store if the corpus outgrows a single Postgres instance.
